01 / 核心理念

IMA 是大脑，WorkBuddy 是手脚

两者配合的核心逻辑很简单：IMA 提供云端知识库 + 语义搜索，WorkBuddy 负责自动消化、整理和定时维护。一个负责「记住」，一个负责「干活」。

🧠

IMA 知识库

云端语义搜索引擎。丢进去的任何东西——网页、文件、笔记——都能被自然语言检索到。不需要精确关键词，说人话就能搜。

🤖

WorkBuddy Agent

自动化执行引擎。能读网页、写笔记、调 API、定时跑任务。把「手动整理知识」变成「自动消化知识」。

🔄

飞轮效应

素材进库 → AI 消化成笔记 → 问答沉淀回库 → 自动化持续采集。知识库越用越丰富，检索越用越精准。

💡
最小闭环 > 完美架构
不要一上来就建完美的分类体系。先跑通「采集→消化→入库」这个小循环，有了真实使用反馈后再优化分类。空架子没有任何价值。
02 / 三层架构

原始素材 → AI 消化笔记 → 结构化知识

知识不是丢进去就完了。按三层架构组织，让每一层都有明确的价值——原始层保证可溯源，消化层保证可理解，结构层保证可检索。

📦
原始素材层
网页、PDF、文件
import_urls / 上传文件
⬇ import_doc
📝
消化笔记层
AI 摘要 + 结构化笔记
关键要点 / 决策 / Q&A
⬇ add_knowledge (media_type=11)
🧩
知识库检索层
语义搜索 + 推荐问题
search_knowledge
⚠️
消化不是复述
AI 消化笔记的核心价值是「提取决策点和行动项」，不是把原文换个说法再说一遍。好的消化笔记应该让读者 30 秒内判断「这篇文章对我有没有用」。
03 / 完整工作流

从采集到飞轮，五步闭环

每一轮循环都在让知识库更值钱。以下是完整的操作流程，每一个环节都有对应的 API。

Step 1 · 分类建库

按领域拆分 3-5 个子知识库（如「大模型技术」「产品方法论」「行业动态」），避免一个大杂烩。用 search_knowledge_base 查看现有库，按需用 IMA 客户端新建。

Step 2 · 批量导入原始素材

用 import_urls 一次添加 1-10 个网页。文件用上传流程。按方向分批导入，每批对应一个子领域。

Step 3 · AI 消化为结构化笔记

每批素材消化为一篇笔记，包含：核心观点、关键数据、决策点、延伸问题。用 import_doc 创建笔记。

Step 4 · 笔记关联到知识库

用 add_knowledge（media_type=11）将笔记链接到知识库。这样笔记内容也能被语义搜索到。

Step 5 · 设置自动化飞轮

用 WorkBuddy 的 automation_update 创建定时任务，周期性采集+消化+入库，让知识库自己长大。

04 / API 速查

核心接口一览

所有接口基于 https://ima.qq.com/openapi/wiki/v1/，POST + JSON body，需携带 Client ID 和 API Key。

场景 接口 关键参数
添加网页到知识库 import_urls urls[] (1-10), knowledge_base_id
创建笔记 import_doc title, content (Markdown)
笔记关联到知识库 add_knowledge media_type=11, note_info.content_id
上传文件到知识库 check → create_media → COS → add_knowledge media_type, file_info
搜索知识库内容 search_knowledge query, knowledge_base_id
浏览知识库列表 search_knowledge_base query (空字符串=全部)
浏览知识库内容 get_knowledge_list knowledge_base_id, cursor
获取可添加的知识库 get_addable_knowledge_base_list cursor, limit
查看/导出原文 get_media_info media_id
🚫
安全门（文件上传必读）
上传文件有 4 道安全门：GATE 1 类型检查（preflight-check.cjs，视频/音频拒绝）→ GATE 2 命名检查（title 必须等于 file_name）→ GATE 3 重名检查（check_repeated_names，不可替换只能保留两者）→ GATE 4 上传出错即停（COS 上传非零退出码则不执行 add_knowledge）。

常用代码片段

# 批量添加网页到知识库
ima_api "openapi/wiki/v1/import_urls" '{
  "knowledge_base_id": "<kb_id>",
  "urls": [
    "https://example.com/article1",
    "https://example.com/article2"
  ]
}'

# 创建笔记
ima_api "openapi/wiki/v1/import_doc" '{
  "title": "笔记标题",
  "content": "Markdown 内容..."
}'

# 笔记关联到知识库
ima_api "openapi/wiki/v1/add_knowledge" '{
  "media_type": 11,
  "note_info": { "content_id": "<note_id>" },
  "title": "笔记标题",
  "knowledge_base_id": "<kb_id>"
}'

# 语义搜索知识库
ima_api "openapi/wiki/v1/search_knowledge" '{
  "query": "自然语言查询",
  "knowledge_base_id": "<kb_id>",
  "cursor": ""
}'
05 / 知识飞轮

让知识库自己长大

飞轮的核心不是「存储」，而是「复利」——每一次检索、每一次问答，都让知识库变得更厚。三条飞轮策略，按需组合。

数据飞轮

四层闭环：监控（发现数据需求）→ 分析（定位数据缺口）→ 规划（设计采集策略）→ 执行（合成/采集数据）。每一轮让模型更好，更好则吸引更多使用，更多使用则产生更多数据。

📖

编译型知识库

Karpathy 的 LLM Wiki 思路：与其每次从原始文档 Retrieve，不如预先 Compile——把原始素材消化成高质量笔记，检索时直接命中结构化知识。Ingest → Lint → Query。

🎯

CODE 方法

Tiago Forte 的个人知识管理法：Collect（采集一切可能有用的）→ Organize（按可操作性分类）→ Distill（逐层提炼摘要）→ Express（输出验证理解）。与三层架构完美对应。

06 / 自动化

定时飞轮，无人值守

用 WorkBuddy 的 automation 系统设定定时任务，让知识库每周自动采集、消化、入库。

⚡

每周 AI 前沿知识采集

每周一上午 9:00 自动运行，搜索本周 AI 领域重要进展，消化为结构化笔记，导入知识库。

RRULE: FREQ=WEEKLY;BYDAY=MO;BYHOUR=9 自动采集 AI 消化

创建自动化的要点

📋 Prompt 要自包含

automation 运行时没有上下文，prompt 必须完整描述要做什么、搜什么关键词、导入哪个知识库、消化笔记的格式要求。

⏰ 频率别太高

推荐每周一次。每日采集容易堆积未消化的素材，违背「先消化再入库」的原则。宁可少而精，不要多而乱。

🎯 方向要聚焦

每个自动化聚焦一个方向（如「Code Agent 评测」），不要一个大而全的 prompt 试图覆盖所有领域。方向越窄，消化质量越高。

08 / 落地清单

从零开始，照着做就行

按顺序完成以下步骤，即可拥有一个自生长的知识飞轮。

  • ✓
    配置 IMA OpenAPI 凭证 — Client ID 和 API Key 保存到 ~/.config/ima/
  • ✓
    确认目标知识库 — 用 search_knowledge_base 查看现有库，或新建一个
  • ✓
    规划 3-5 个子方向 — 按你关注的领域拆分，每个方向有明确的采集关键词
  • ✓
    按方向批量导入素材 — 用 import_urls 每次添加 1-10 篇网页
  • ✓
    AI 消化为结构化笔记 — 每个方向一篇消化笔记，用 import_doc 创建
  • ✓
    笔记关联到知识库 — add_knowledge (media_type=11) 链接笔记到 KB
  • ✓
    验证检索效果 — 用自然语言搜索，确认素材和笔记都能被搜到
  • ✓
    设置自动化 — 创建定时任务，周期性采集+消化+入库
  • ✓
    问答沉淀 — 每次高质量的问答，考虑沉淀为笔记入库
  • ✓
    定期维护 — 每月审视知识库，清理过时内容，优化分类
🚀
一句话总结
知识库的价值不在于「存了多少」，而在于「能不能被用到」。三层架构保证质量，飞轮机制保证增长，自动化保证持续。先跑起来，再优化。
